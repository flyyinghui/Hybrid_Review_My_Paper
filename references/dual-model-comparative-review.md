# 双模型对照审查模式 (v4-pro + Qwen3.8, 2026-08-19)

用户要求"Hybrid-review 用 deepseek-v4-pro(high, 最大token) + 同时做一个 Qwen3.8 对照审查"时的模式。已验证于 CGICE 论文审查。

## 流程

1. **提取论文关键内容**（摘要 ~2500 字符 + 前 40 条公理/定理 + 数值声明 ~3000 字符 + 结论 ~2000 字符 + Lean 统计），构建 <50K chars 的统一 prompt。
2. **并行/串行调用双模型**：
   - deepseek-v4-pro：`reasoning_effort="high"` + `max_tokens=32768` + `temperature=0.0`。⚠️ high reasoning 会吃光 max_tokens 返回 content 空——prompt 里必须写"简洁思考，直接输出结论，不要在思考中长篇推导"。实测 content=4476 字符 / 128s。
   - Qwen3.8:27b-Q8_0（llama-server 8081）：`chat_template_kwargs: {"enable_thinking": False}` + `max_tokens=3000`。⚠️ 27B 生成长报告极慢（3000 token ≈ 666s = 11 分钟），用 background + notify，不要前台等。
3. **综合去重 + 交叉验证 + 剔除误判**：两个模型结论重叠的部分是高置信 P0；单模型独有发现需独立验证；剔除误判（见下）。

## 关键洞察：模型只看到提取片段会误判

双模型审查的是**提取的摘要/关键片段**（不是全文），因此：
- **会漏掉正文已有的完整推导**：v4-pro 质疑"g_TC 由 η_k 推出但缺公式"，Qwen3.8 追问"η_k=72/35 的 72 来源"——但 CGICE §7.3 行 602-610 **已有完整推导** η_k = C₂(adj)·h^∨/dim = 12×6/35 = 72/35 和 g*² = 4π²|η_k|/b₀ = 24π²/35。两者都误判。
- **误判根源**：审查 prompt 只喂了摘要+片段，摘要里确实没写完整公式。**综合时必须回查正文对应章节**（grep 关键词），确认质疑项是否已在正文存在，再定性为"真实缺失"还是"误判"。

## 双模型互补性

| 模型 | 强项 | 弱点 |
|------|------|------|
| v4-pro (high) | 发现真实几何错误（P0-1 SU(6)/SO(6) 20维 vs SL(6,C)/SU(6) 35维 维度混淆）| 评分偏苛刻 (2/10)，误判已有推导 |
| Qwen3.8 (27B) | 追问参数来源（η_k 的 72 是否表示维度）、公理映射表建议 | 评分偏宽松 (4/10)，慢 (666s) |

综合后（修复真实 P0 + 剔除误判 + 诚实标注）才是最优结论，而非简单取平均。

## 本次验证的具体发现（CGICE）

- **P0-1（真实，已修复）**：摘要混用"35维 SL(6,C)/SU(6)"和"compact dual SU(6)/SO(6)"（20维，35−15=20）。修复：摘要明确区分两对象 + 标注 SU(6)/SO(6) 是 20维紧对偶（Lichnerowicz-Obata λ₁=|ρ|²=35）。
- **P0-2（真实，已校核）**：公理计数 73 vs 25/62 冲突 → 附录 A.4 更新分类映射表（25核心+3谱隙+7EEM+29状态+8数值+1spec_gap=73）。
- **P1-1（真实，需澄清）**：λ_∥=35 被误读为"群维度"，实为 Weyl 向量范数 |ρ|²（doubled 归一化）。摘要补写澄清。
- **P1-2/P1-3（误判）**：η_k 来源 + g_TC 公式已在 §7.3 存在。
