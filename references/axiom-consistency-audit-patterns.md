# 公理体系自洽性审计模式（Lean 形式化证明终审）

本文件记录论文+Lean 终审中**公理逻辑自洽性**层面的缺陷模式。与
`lean-arithmetic-audit-patterns.md`（算术/战术层面）互补——那个讲"证明体空转"，
这个讲"公理集合本身不自洽/不自量"。2026-08-16 三篇 SL(6,C) 论文终审共同揭示。

---

## 模式 1：公理体系可证 False（爆炸原理 ex falso）【最高优先级，阻断级】

**症状**：论文声称"0 sorry / 0 active axiom"即"形式化验证通过"，但公理集合在经典
逻辑下不自洽——从矛盾公理可推出任何命题（包括 False），所以全部"定理"**及其否定**
都可证。"0 sorry" 是一张空头支票，不自洽的公理集比 sorry 更糟。

**CGICE V9.1 案例（决定性）**：两条独立矛盾，每条都足以让体系坍缩：

- **矛盾 CON-1（A6+A10 vs A17）**：
  - A6：`I_cycle t = V_eff t · (2π/λ₁)`（= V_eff·6π/35）
  - A10：`V_eff·(2π/(35/3)) = (35/3)(V_eff/Λ_CC)`（= I_eq）
  - 联立强制 `I_cycle = I_eq`
  - A17：`I_cycle t ≠ I_eq (...)`（作者注释"prevent trivial solution"）
  - **直接矛盾**

- **矛盾 CON-2（A9 vs A17，更简单，连 A6/A10 都不需要）**：
  - A9：`I_cycle 0 = I_eq (V_eff 0) (Λ_CC 0)`（初始条件公理）
  - A17：`∀t, I_cycle t ≠ I_eq`（取 t=0 即得 `I_cycle 0 ≠ I_eq`）
  - **在 t=0 处直接矛盾**

**检测技巧**：审查"防止平凡解"类公理时，立即检查它是否与 (a) 其他公理链推出的
等式、(b) 初始条件公理的全域量化实例 相矛盾。`∀t, X(t) ≠ Y(t)` 型公理 + `X(0)=Y(0)`
型初始条件 = 秒级矛盾。

**根因诊断**：作者在 Lean 注释里自认 "A6+A10+A4 force I_cycle=I_eq"，却追加 A17
"防止平凡解"——**用矛盾公理覆盖被推导出的等式**。正确修法是改 A6/A10 系数使链
不闭合，让非平凡动力学成为主方程（A16）的**解**，而非矛盾公理。

## 模式 2：矛盾迁移（迭代修复引入新矛盾）

**症状**：前轮发现"公理 A+B 强制 V_eff≡0 平凡解"，作者修复方式是引入自由参数
（A 改为 `= α·V_eff`），表面消除矛盾。但 α 被另一条公理钉死为某值后，**恰好复活
了原等式**，只能靠矛盾公理硬撑。

**三峰 V16 + CGICE V9.1 共同案例**：α 被 A15 钉死为 `α = 6π/35`，而
`6π/35 = 2π/λ₁ = τ_CGICE` —— 修复想消除的等式以另一个名字回来。

**检测技巧**：审查"引入自由参数消除矛盾"的修复时，grep 该参数的所有出现点。若它
同时被 (a) `def` 定义、(b) 另一条 `axiom` 钉死具体值、(c) 与某常数（如 2π/λ₁）
数值相等，则"自由参数"是误称，矛盾未真正消除。

**衍生信号**：`0 < α ∧ α < 1` 这类范围公理在 α 已被钉死为具体值（且该值确在范围内）
时是**空真冗余**，属零信息公理。

## 模式 3：表演性诚实（@[honest_axiom] 是注释文本，非真实 Lean 属性）

**三峰 V16 案例（本轮最重发现之一）**：

- Lean 中 26 处 `@[honest_axiom]` + 8 处 `@[phenomenological]` **全部是注释掉的文本**
  （`-- @[...]`），真实 Lean attribute 行数 = **0**。
- 但论文摘要/关键结果反复声称"声明为 @[honest_axiom] 或 @[phenomenological]"——
  这是对代码状态的错误陈述。
- 编译语义上注释文本等于零，无法机器审计（`#print axioms` 看不到任何标签）。

**判定**：文档层是真披露，机制层是假标注。这是"外观像严格披露系统，实质是装饰性
注释"的典型。

**检测技巧**：`grep -c '^@\[honest_axiom\]' file.lean`（行首无 `--` 前缀）应 > 0。
若论文声称"声明为 @[honest_axiom]"但 grep 只命中 `-- @[honest_axiom]`，即表演性诚实。
真实实现需自定义 Lean attribute：`syntax "honest_axiom" attr : attr` + `@[honest_axiom] axiom ...`，
再用 `#print axioms` 机器审计。

## 模式 4：公理计数全线失守（修订后统计口径 stale）

**症状**：论文多处声称的公理/定理/引理/行数计数与实际 Lean 文件全线不符，且修订
越大、矛盾越严重（从三处恶化到四处）。

| 论文 | 声称 1 | 声称 2 | 声称 3 | 实测 |
|---|---|---|---|---|
| 三峰 V16 | 14 axioms | 41 axioms | 11+8=19 | **66 axiom / 53 thm / 26 lemma / 1979 行** |
| CGICE V9.1 | 14 axioms | 25 axioms | — | **39 axiom** |

**关键教训**：一个以"透明声明假设"为核心的披露系统，连假设数都数不清，直接摧毁
可信度。修订后必须重新 grep 计数，把全文统计同步为唯一实测值。

**检测技巧**：终审第一步就 grep `^\s*axiom\s`（排除注释行）得到 ground truth，再与
论文摘要/§3/附录/Lean 头注释四处逐一比对。任何一处不一致即 C3 型缺陷未收敛。

## 模式 5：公理重述当证明（T = exact axiom）

**症状**：定理体是 `theorem t : ... := by exact some_axiom`——把结论声明为公理后，
"定理"只是公理重述，零数学内容。

**CGICE V9.1 案例**：T1 = `exact a16_master_equation`、T3 = `exact a22_legendre_duality_diff`。
"诚实降级为公理"比"伪造成 0=0 假证明"是进步，但**以"定理/已完全验证"名义呈现仍是误导**。

**检测技巧**：grep 每个 theorem 的证明体。若 `:= by exact <axiom名>` 或
`unfold + norm_num`（算术恒等式）占多数，则"8 个证明全部零内容"成立，形式化验证空转。

## 模式 6：非紧对称空间离散谱错误

**症状**：`axiom a3 : λ_k = k·λ₁` 声称 Witten Laplacian 有等差离散谱。但
SL(6,C)/SU(3,3) 是**非紧**对称空间，谱是**连续谱**（Plancherel 测度绝对连续），
不存在离散本征值 λ_k=k·λ₁。即使取紧对偶，谱也由 Freudenthal 公式 ⟨μ+2ρ,μ⟩ 给出，
非等差。

**判定**：对紧/非紧情形皆错的公理。这是"公理化了一个数学上错误的命题"。

**连带陷阱**：等差离散谱 λ_k=k·λ₁ 与"双谱隙"叙事内部冲突——λ₁=35/3 时梯谱为
35/3、70/3、35，故 λ_∥=35 实为第 3 个本征值，与"纵向/横向两独立谱隙"不兼容。

## 模式 7：流形标量占位（A1 = ℝ→ℝ 恒等函数）

**症状**：`axiom a1_geometric_manifold : ℝ → ℝ := fun x => x`——整个"35 维流形"在
形式化中坍缩为实数轴上的恒等映射。Killing 度规、结构常数、T*M 辛形式、35×35
协方差全部缺失。**形式化证明的对象与论文声称的对象根本不是同一个。**

**审阅建议（8/16 深度审阅原文要求，未落地即记未吸收）**：用 Mathlib 的
`ChartedSpace (EuclideanSpace ℝ (Fin 35)) M` + `SmoothManifoldWithCorners` 重铸，
`axiom V_eff : M → ℝ` + `ContMDiff` 声明光滑性。即便动力学只关注标量，状态域必须
植根于拓扑流形 M。

## 模式 8：声称 verified 但定理不存在（虚假陈述，学术不端级）

**症状**：论文正文/结论声称 "theorem t4_topological_charge_conservation 已完全
验证/formalized in Lean"，但 Lean 文件中**无此定理**，仅一行注释 "UNDER DEVELOPMENT"。

**CGICE V9.1 案例**：T4 拓扑荷守恒、A23-A25 公理、若干数值引理，论文声称全部
形式化，实际 Lean 只到 A22。

**判定**：这是比"不够严谨"严重得多的问题——对形式化验证的**虚假陈述**，学术不端级。

**检测技巧**：论文声称的每个 theorem/axiom 名称，逐一 grep Lean 文件确认存在性。
"声称 verified 但 grep 不到" = 阻断级缺陷。

## 验证技术：Lean 4 最小文件编译复现矛盾

自洽性审计要给出硬证据，不要只做静态推断。用最小 Lean 文件（无需 Mathlib，用
`opaque` 符号忠实抽象公理的精确结构），编译出 `False` 证明：

```lean
-- /tmp/false_proof.lean
opaque I_cycle : ℝ → ℝ
opaque I_eq : ℝ → ℝ → ℝ
opaque V_eff : ℝ → ℝ
opaque Λ_CC : ℝ → ℝ
axiom a6 (t : ℝ) : I_cycle t = V_eff t * (2*π / (35/3))   -- A6 抽象
axiom a10 (t : ℝ) : V_eff t * (2*π / (35/3)) = I_eq (V_eff t) (Λ_CC t)  -- A10 抽象
axiom a17 (t : ℝ) : I_cycle t ≠ I_eq (V_eff t) (Λ_CC t)   -- A17 抽象

theorem boom : False := by
  have h1 : I_cycle 0 = I_eq (V_eff 0) (Λ_CC 0) := by
    rw [a6 0, a10 0]
  exact a17 0 h1
```

`lean /tmp/false_proof.lean` 编译通过 `boom` 即坐实矛盾。关键在识别原文件中的
`def` 使某两项**定义相等**（如 `def λ₁ := 35/3` 使 A6 右端 = A10 左端），传递即得矛盾。
