# 开放桥深化的三个诚实性陷阱（作者侧）

> 来源：2026-10-02 光速时空分界面证明的 5-agent 终审（MAJOR REVISION）。
> 场景：形式化证明中，把 [O] 开放桥「往前推一步」时，容易用 trivial / 同义反复构造
> 假装成「实质推进」。这三个陷阱是规则组 A2/B3/B4 的**作者侧版本**——审稿规则负责检测，
> 本文负责**预防**。

---

## 三个陷阱

### 陷阱 1：循环定义（把 codim 调成匹配值）

为了让结论「光速比值 = 分界面维度」成立，把分界面的 codim 从 2 悄悄调成 3
（把 longitudinal timelike axis 算进边界），再用这个调过的 codim 去「证明」比值=分界面维度。

- **检测信号**：结论依赖的量，其定义在证明前被调整以匹配结论。
- **修复**：把 codim=3 明示为 [M] 匹配输入，而非 [T] 证明。定理降级为条件定理。

### 陷阱 2：校准伪装（自由参数伪装成推导）

引入自由参数 ω₀/k₀，再设为 c/3，然后声称「recover c = 299792458」。

- **检测信号**：「recover X」是用 X 定义参数再「恢复」X（循环代入）。
- **修复**：标注为 dimensional rewriting / calibration input，非推导。删掉「recover」表述。

### 陷阱 3：状态升级（trivial 构造标记为 [T]）

「写下洛伦兹二次型 diag(-1,1,1,1) + 验证 (1,0,0,0) 给 -1<0」
（任何 4D 实向量空间都允许）被标记为 [T] 定理并声称「深化开放桥」。

- **检测信号**：定理体 unfold 后只剩 rw[定义] + norm_num/linarith；标题/摘要用
  "advance/deepen/prove/proof" 描述 trivial 构造。
- **修复**：标注 trivial construction / sanity check，明示**不解决**选择机制开放桥。

## 通用检测信号（5-agent 终审实际抓到的）

| 信号 | 对应陷阱 |
|---|---|
| 定理名声称「X 是 Y」（如 `light_speed_equals_phase_boundary_dimension`）但证明体只是「比值=Z」 | 语义跳跃（陷阱 1） |
| 「recover c」循环代入 | 校准伪装（陷阱 2） |
| 定理体 = rw[定义] + norm_num，但标题称「deepening/advance/proof」 | 状态升级（陷阱 3） |
| 摘要/标题用 "advance two of the open bridges" 描述 trivial 构造 | 状态升级（陷阱 3） |

## 与规则组的关联（审稿侧检测）

- 陷阱 1 = 规则组 **A2**（循环定义）的作者侧版本
- 陷阱 2 = 规则组 **B3**（校准伪装成推导）的作者侧版本
- 陷阱 3 = 规则组 **B4**（状态升级过度声称）的作者侧版本

**关键洞察**：审稿规则 B3「校准伪装」和 A2「循环定义」已经存在，但它们是**审稿侧**
检测。本次教训是：**作者自己做「开放桥深化」时，这三个陷阱会以「推进」的正面措辞
出现**，比审稿时的「缺陷」更难自查——因为作者带着「我想把桥推进一步」的动机，
而 trivial 构造恰好满足了「往前推」的表面形式。

## 作者侧自检清单（深化开放桥前必查）

1. 我要「推进」的开放桥，是否只是**写下一个已知对象 + 验证一个平凡性质**？
2. 我引入的参数，是否被**设为观测值来「恢复」结论**（校准伪装）？
3. 我「证明」的结论，其依赖量的定义是否在证明前**被调整过**（循环定义）？
4. 定理名是否**声称了比证明体更多的东西**（语义跳跃）？
5. 标题/摘要的 "advance/deepen" 是否描述了一个 trivial 构造？

**诚实纪律**：宁可把 trivial 构造诚实标为 trivial，也不伪装成定理。把 [O] 开放桥
「往前推」时，诚实的表述是「结构性观察 / trivial 构造 / 量纲重写」，不是「推导 / 证明 / 深化」。
