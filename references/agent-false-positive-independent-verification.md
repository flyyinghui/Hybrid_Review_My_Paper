# Agent 集体误判 + 独立核验 (Agent False-Positive + Independent Verification)

**触发词**: "多个审稿人同时报告数值矛盾" / "agent 集体误判" / "摘要数值矛盾" / "独立核验 agent 数值发现" / "数值 agent 重算错了"

## 何时用

当部署多 agent 评审后，**多个 agent 同时报告同一个"数值矛盾/计算错误"**时，不要直接采信并作为 P0 转达给用户——先做三层独立核验。本模式的元教训（2026-09-04 V17 终审验证）：**agent 的 P0 发现本身可能是错的**，尤其两类：(a) 语法歧义导致集体误读；(b) agent 自己的重算用了错误惯例。

## 三层核验（按顺序）

### 1. 语法歧义检测（最常见集体误判根因）

案例：V17 摘要
> "The initial ratio 5.00 evolves to the current observed ratio 5.47: 0.46% of baryonic matter collapses into black holes and is amplified by (1+z_eff)³ ≈ 148..."

- **5 个 agent 全部**读成 "0.46% 嬗变驱动 5.00→5.47"，判定算术矛盾（5.47/5.00=+9.4%，0.46% 只能给 5.02）。
- **独立核验**：`0.0046 × 148 = 0.68 ≈ Ω_DE` —— 这条 "0.46% → Ω_DE" 链**算术自洽**；`5.00 → 5.47` 是**另一条**独立演化链（黑洞嬗变）。冒号 `:` 把两条无关链拼接导致歧义。
- **真实问题 = 写作清晰度（P1），非算术错误（P0）**。

**规则**：多个 agent 报告"数值矛盾"时，先自己重算算术，再检查是否标点（冒号/分号）把两条独立链拼接。宁可降级为 P1 写作问题，不误判为 P0 算术错误。

### 2. Agent 重算惯例错误检测

案例：数值 agent 声称 `b₀=12` 错误（"应为 82/3≈27.3"）。实际：
`b₀ = (11/3)·C_A − (4/3)·N_f·T_F = (11/3)·6 − (4/3)·15·(1/2) = 22 − 10 = 12` ✅ 正确。
agent 误用 `(4/3)·15 = 20` 而非 `(4/3)·15·(1/2) = 10`（漏了基本表示 T_F=1/2 因子）。

**规则**：agent 的独立重算本身可能有惯例错误——Dirac vs Weyl 费米子（4/3 vs 2/3 系数）、T_F=1/2 基本表示因子、卡西米尔归一化、Killing 度规约定。凡 agent 声称"论文算错"且涉及 β 函数 / 卡西米尔 / 群论不变量 / 归一化时，**自己再算一遍**再定性。

### 3. 机械审计先行（ground truth 锚定）

部署 agent 前先自己产出 ground truth，作为 agent 发现的校准基准：
- Lean 注释剥离后的精确统计（grep 含注释内弃用声明会虚高）
- 论文声称统计 vs Lean 实际活跃声明对照
- 逐条数值 Python 精确重算（打印"独立重算值 vs 论文声称值"）

## 与现有 reference 的关系

- 本模式**纠正**了 `math-calculation-accuracy-review.md` 的模式 #7（"5.00→5.47 由 0.46% 嬗变"被记为"循环校准链"）。实际根因是**语法歧义**（两条独立链被冒号拼接），非循环校准。若该摘要句子再次出现，应按"两条链拆分"处理，而非"循环校准"。

## 交付格式

合成报告时必须附一张 **"agent 误判纠正"表**，逐条标注：agent 声称 / 独立重算结论 / 纠正定性（P0→P1 / P0→非问题）。这是诚实性要求——不把 agent 的 false-positive 原样转达给用户。
