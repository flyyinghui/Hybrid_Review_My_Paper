# 多论文系列审查的母框架先决 + 三个陷阱

2026-08-29/30 四篇 SL(6,C) 系列论文（CGICE V9.1 / 时空相 V17 / 中微子 V63 / 三峰 V16）联合审查实录。核心教训：

## 1. 母框架先决（最重要，P0 级）

**现象**：初审未加载 `SL6C_Unified_Geometric_Dynamics_Framework.md`（2026-08-12 生成的统一框架），把四篇论文的"跨论文参数不一致"误判为 7 个 P0 矛盾：
- g_TC 四值（2.60/1.50/0.5/2.83）→ 误判为"矛盾"，实为 UV=0.5 裸耦合 / IR=2.60 FRG 定点 + 两处误用
- λ_KLS 35 vs 35/3 → 误判为"数学错误"，实为双重谱隙（λ_∥=35 纵向 / λ_⊥=35/3 横向空间均分）

**加载框架后重新裁定**：7 个 P0 全部降级为"标注澄清"，评分从 5.0–6.5 上调至 6.5–7.8。

**规则**：审查一组**共享同一理论框架**的系列论文时，必须先查找并加载母框架/统一框架文档（umbrella framework doc）。同一参数在系列内出现多个值，**不一定是矛盾**——可能是：
- UV/IR 跑动耦合的两端（g_TC(UV)=0.5 vs g_TC(IR)=2.60）
- 双分量谱隙的正交分解（λ_∥ 纵向 vs λ_⊥ 横向）
- 两个实形式的角色分工（SU(6) 紧致=谱分析 / SU(3,3) 非紧=物理相）
- 校准值 vs 推导值（N_e=80.6 标注 CALIBRATION）

**判定流程**：发现跨论文参数不一致 → 先 grep 母框架文档是否已定义该参数的多个角色/取值 → 若有，判定为"需标注澄清"而非"矛盾"；若无，才是真矛盾。

与 `reviewer-contradiction-vs-framework-phases.md` 的区别：那个是"外部审稿人误判矛盾"，这个是"**审查者自己（初审）未加载框架导致误判**"。两者互补。

## 2. v4-flash 多论文审查会幻觉论文编号

**现象**：v4-flash 生成评分表时，把四篇论文（CGICE V9.1/V17/V63/V16）误写为 V16/V17/V63/**V18**——漏掉 CGICE V9.1，幻觉出 V18。

**修复**：在 prompt 里**显式列出所有论文的正确名称 + 各自角色**，并加"严格使用这些编号，禁止幻觉其他编号"。

```python
【四篇论文的正确名称与角色(严格使用这四篇，禁止幻觉其他编号)】
1. CGICE V9.1 = 第二层动力学核心
2. 时空相演化 V17 = 第一层几何基础
3. 中微子凝聚 V63 = 第三层场论实现
4. 三峰引力波 V16 = 第四层现象学
```

**通用规则**：任何多论文（≥3 篇）审查的 prompt，都必须内嵌一个"论文名称 ↔ 角色"清单，否则 v4-flash 会丢论文或幻觉编号。

## 3. 评分表"原评分"列会自编数值

**现象**：v4-flash 生成"原评分 → 调整后评分"表时，用的"原评分"是它自编的（CGICE 6.0/V17 5.5/V63 5.0/V16 6.0），而非我实际报告的评分（5.5/6.0/6.5/5.0）。

**修复**：生成后手工核对"原评分"列，与上一轮审查报告的实际分数比对，不一致则 patch 修正。

**通用规则**：多版本审查的评分演进表，"原评分"列必须由我核对后填实际值，不能信任 LLM 自编的基线。

## 4. 审计脚本嵌套块注释假阳性（sorry 检测）

**现象**：`proof_consistency_audit.py` 对中微子 V63 报 `sorry=4 → BLOCK`，但这 4 个 sorry 全是注释文字（"0 active sorry" 声明、CHANGELOG 表格）。

**根因**：审计脚本用 `re.sub(r'/-.*?-/', '', lean, flags=re.S)` 剥块注释，但**非贪婪 `.*?` 无法处理嵌套的 `/-`**——中微子 V63 的 Lean 有大量嵌套块注释（`/- ... /- ... -/ ... -/`），剥除在第一个 `-/` 提前终止，后续块注释内部行漏到 active 列表。

**验证**：`grep -n 'sorry' file.lean` 逐行看上下文——4 处都在 `--` 行注释或块注释尾部说明里（如 "The file compiles with zero `sorry` keywords"）。

**规则**：审计脚本报非零 sorry/admit/trivial 时，**必须 grep -n 逐行确认上下文**，排除嵌套块注释导致的假阳性。这与 ars-awa-hybrid-review Pitfall 4（Lean Stats Regex Trap）一致，但根因更细：是嵌套 `/-` 导致块注释剥除不完整，而非简单的注释漏滤。

**黄金门控规则（GitHub 反馈 2026-08-29 修复固化）**：确认是**真 active sorry**（未完成证明）后，gate **必须 BLOCK**。此前 `proof_consistency_audit.py` 的 bug 是 `n_sorry` 只进 `stats.active_sorry` 从不加入 `blocks`——导致含 sorry 的未完成证明以 `gate=PASS` 通过审计门（审计形同虚设）。修复：加"检测 0"，`if n_sorry > 0: blocks.append(...)`。任何 Lean 一致性审计的第一条门控都是 `active_sorry == 0 否则 BLOCK`，比公理自洽性/表演性诚实等六类 P0 缺陷更基础。
