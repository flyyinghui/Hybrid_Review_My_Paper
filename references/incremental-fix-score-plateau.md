# 增量修复 vs 评分天花板 — 混合审阅经验

## 现象

V5 论文评分 1.3/10 → 修复 P0 问题 → V6 评分 1.4/10（+0.1）。

5位审稿人一致认为修复是"表面性"的：去除了 ad-hoc 归一化因子但 N_e 值仍未推导、添加了 GW 应力-能张量但作为公理而非推导、声称 N_eff=3.046 但未从几何推导。

## 根因

当论文的**核心主张**（GW = DM、KLS 间隙→频率、DM:B = 5:1）本身依赖于未验证的公理体系时，**任何不解决公理根基的修复都不会改变审稿结论**。

审稿人区分两类修复：
- **A类（结构性）**：从公理推导出结果，解决循环论证 → 可能提升评分
- **B类（表面性）**：添加公式声明、修正算术错误、调整标签 → 评分几乎不变

## 判断标准

在决定做增量修复前，先检查：
1. 论文的核心结果是否可直接从公理体系计算（而非假定）？
2. 关键数值是否独立可验证（而非拟合/选择）？
3. Lean 证明是否包含实质推导（而非 `norm_num` + 公理声明）？

如果 3 个答案都是"否"，增量修复不会改变审稿结果。应诚实降级为"推测性框架"投稿。

## 案例

2026-07-25: Triple GW V5→V6 评分持平。V5 识别 6 个 P0，V6 修复了 4 个表面问题，但核心循环论证未改变。

## 关联陷阱：DOCX 提取过短导致审阅无效

当 DOCX 被 XML 级编辑损坏时，提取的文本可能仅 488 字符（而非预期的 47K 字符）。审稿人只能看到 7 段碎片文本 + Lean 证明，导致评分反映的是"不完整论文"而非实际修改。

**检测**：提取后立即检查 `len(paper_text)` — 如果 < 5000 字符（对于科学论文），DOCX 已损坏。

**修复**：从 V5 基础重建 DOCX（python-docx 复制+修改，非 XML raw string replace），重新提取后再次验证长度。
