# 审稿"混用/矛盾"发现 vs 框架相结构 — 反向裁决模式 (2026-08-20 CGICE V9.1)

## 触发场景
- 审稿报告把"论文混用两个对象 X/Y"（如 CGICE 论文 SU(6) vs SU(3,3) 全篇混用）定性为"二选一、必须统一"
- 双模型/多模型对"统一方向"达成一致建议（如"统一为 SU(6)"）
- 用户问"根据母框架的物理动机，评估审稿意见是否正确" → 触发反向裁决

## 核心教训 1：审稿的"矛盾"定性本身可能是错的
当审稿报告把"论文混用对象 A 和对象 B"定性为"二选一、必须统一"时，
**先回溯母框架是否把 A/B 定义为同一演化的两个端点/相**，再决定是否接受该定性。

CGICE V9.1 案例：审稿报告 P0-1 判定"SL(6,C)/SU(3,3) 与 SL(6,C)/SU(6) 混用是致命矛盾，
应全文统一为 SU(6)"。但母框架 `SL6C_Unified_Geometric_Dynamics_Framework.md` §6.1 确立：
- SU(6) = UV 端欧几里得几何相（紧致正定，无时间方向）
- SU(3,3) = IR 端分裂几何相（不定度规，3S+3T 时间涌现）
- 70 维模空间 T*M 是这两个端点的 UV→IR 演化过程（先展开后紧化）

正解：**显式角色分工 + 实截面锁定/Wick 旋转映射**，而非"统一为单一对象"。
- SU(3,3) 保留为 IR 物理相（承载 A1 几何信息流形、中微子 seesaw 非紧扇区 X_nc、时间方向涌现）
- SU(6) 保留为谱分析数学流形（承载 Witten Laplacian 谱、Langevin/EEM 动力学、|ρ|²=35 谱下界）
- "统一为 SU(6)"会摧毁 seesaw 与时间涌现的几何载体；"统一为 SU(3,3)"会摧毁谱分析
  （SU(3,3) 不定度规、谱无下界、无法支撑 Markov 动力学）

## 核心教训 2：双模型共识 ≠ 正确
两个审稿模型对"统一为 SU(6)"达成一致，但都错了——它们共享同一盲点（忽略框架相结构）。
最终裁决必须回溯到理论自身的物理动机，而非模型间的多数票。
（对照已有陷阱"v4-pro 单模型过慷慨"：这里是"多模型共识同样可能共同出错"。）

## 反向裁决检查清单（审稿发现"混用/矛盾"时）
1. 该"矛盾"涉及的两个对象，在母框架中是否是两个相 / 端点 / 实形式？
2. 若是 → 正确修复是"角色分工 + 转换映射"（Wick 旋转、实截面锁定、Cartan 对合）
3. 检查"统一为单一对象"是否会摧毁某一端点的合法物理载荷（如 seesaw、谱分析）
4. 检查转换映射中的归一化/实形式修正因子（如 η_Cartan≈0.997）是否已应用到所有依赖参数
5. 审稿报告须与母框架交叉核对后再接受其"矛盾"定性

## 相关陷阱
- proof-paper-cross-ref-revision 已有"跨论文一致性"陷阱，本条是反向的：
  审稿报告的"不一致"定性本身可能错误，须以母框架的物理动机为准。
- 数学技术层 vs 物理相层的区分：同一对象可在"数学分析流形"与"物理相"两个层面
  扮演不同角色，混用不是错误，缺"角色分工说明"才是错误。
