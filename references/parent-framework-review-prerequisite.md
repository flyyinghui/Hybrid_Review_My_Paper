# 母框架审查前置 — 审查共享母框架的多篇论文前必须先加载母框架文档

**触发场景**：用户要求联合审查一组**共享同一个母框架（master/unified framework）**的多篇论文（如 SL(6,C) 四论文系列：CGICE V9.1 / 时空 V17 / 中微子 V63 / 三峰 V16）。

**核心教训（2026-08-29 验证）**：不先加载母框架文档直接做多论文联合审查，会把框架**已经解决的机制**误判为"跨论文 P0 矛盾"，给出过严的评分和错误的修改方向。重新加载母框架后重裁定，大部分"矛盾"降级为"标注澄清"。

## 正确流程（审查前 4 步）

1. **定位母框架文档**：问用户或搜索共享框架文档（如 `SL6C_Unified_Geometric_Dynamics_Framework.md`），不要直接开始审查。
2. **提取母框架的"已解决机制清单"**：母框架通常已经预先解决了跨论文参数不一致（如双重谱隙、UV/IR 跑动、实形式角色分工）。列出这些机制作为审查的"已知答案"。
3. **大脑 recall 验证框架机制**：用 brain.recall() 召回母框架的关键数学对象（如非紧对称空间无正谱隙、紧对偶的首特征值），确认框架机制的数学正确性。
4. **区分三类重裁定**，而非一刀切判"矛盾"：
   - **框架已解决机制** → 降级为"需在论文正文标注澄清"（不是矛盾，是论文没写清楚框架已定的角色分工）
   - **真错误需删除** → 误用值（如把 λ_KLS=35 而非 λ_⊥=35/3 代入公式得到的 g_TC=1.50），必须删除
   - **需标注澄清** → 诚实声明缺失（如 H₀ 校准性质、honest-axiom 标签）

## 关键陷阱

1. **"矛盾"≠"错误"**：跨论文参数不一致可能只是同一框架的不同物理相/能标端点的量（UV/IR 跑动、纵向/横向谱隙、紧致/非紧实形式）。先查母框架是否已定义角色分工，再判矛盾。
2. **审查报告要保留"框架未解决的真问题"清单**：母框架解决大部分矛盾，但仍有真问题（如 N_e 开放问题、幻影公理、关键推导缺显式形式）。这些不能因为"框架已解决大部分"而漏掉。
3. **评分要区分两个视角**：单篇独立审查（不加载框架）会给过严评分；加载框架后评分上调是合理的，但要说明调整理由（哪些矛盾是框架已解决的）。
