# referee-sim 框架预审（Stage 0）— BootLoops 移植

> 来源：BootLoops `referee-sim`（Matthew D. Schwartz）。落地为 `ars-awa-hybrid-review` Stage 0。
> 定位：任何 5-agent 事实审稿（Stage 2a/3/4a）**之前**必须跑的一轮 implicature 审计。

---

## 一、为什么需要独立 Stage

**事实核查（fact-checking）与框架核查（frame-checking）是两种正交审计。** 规则组 A–F 全是事实核查——逐句真值 + 计数一致 + 引用真实 + 方法对齐。referee-sim 审计的是 **implicature：每种读者会「相信什么」**。

一个每句都有出处、每处都诚实的文档，仍能通过**组装**误导读者：

- caveat 全在正文，印象在摘要形成；
- 对比诚实，但 baseline 是没人用的那个；
- 定理真实，但读者离开时相信它覆盖了它排除的情形。

**这类失败能穿越多轮诚实性 pass，只在外部专家最终读到文档时才浮现——那时印象已在唯一重要的读者（审稿人）脑中形成。** 这就是 Stage 0 必须在任何事实审稿前跑的原因。

## 二、七步流程

### 1. 显式枚举受众（写下来）

列出每一个可能给这份文档写报告的社区。来源按序：

1. 引言里 "this matters to X, Y, Z" 那句话——**那是契约**，每个被点名的社区拿一行。
2. 文档**借用其方法**的每个社区——用他们的机器就援引了他们的标准，无论文档是否回应。
3. 文档**取其结果作输入/对比**的每个社区。
4. **incumbent（现任者）**：当前把文档声称做得更好/更快/不同的事的那个人。即使引言从没提他们——**尤其那时**。
5. **practitioner（实践者）**：会据此行动的人，问的从来不是"有意思吗"而是"我依赖它会不会崩"。
6. 期刊的 general reader：决定哪些 claim 必须在不靠周边专业知识时也站得住。

**两条硬规则**：
- 任何借来作权威的社区（方法/数据集/基准/动机应用）**无一例外拿一行**——"缺失受众"失败几乎总是这类。
- **跨学科声明抬高门槛**。每个额外受众带来自己的标准反对意见，outsiders 读得比 insiders 更苛刻：他们套用本领域一阶标准，没有理由给 benefit of the doubt。

### 2. 生成每个受众的最强「标准」反对——双轴

每个受众两行，分别生成：

- **Correctness（正确性）**："这对吗？在我社区关心的情形下成立吗？"
- **Novelty（新颖性）**："这新吗？相对我们已有的东西，精确的进展是什么？"

两轴是**不同的审稿报告**，答在不同位置——correctness 在 scope 陈述/对照/比较里，novelty 在引言定位和 prior-work 交锋里。只答一轴就死在另一轴；混淆两轴产生特征性杂种：证明了一切却从不说新在哪，或声称 first 而 incumbent 社区的 SOTA 未受检。

"标准"= 该社区审稿人**第一个问的**，不是奇特的。按社区类型校准：

- **工程/应用**："这扛得住 generic case（generic 噪声/输入/对抗设定）吗，还是只扛你研究的 structured case？"
- **实验家**："仪器到底测什么？和你算的是同一个对象吗？预测的哪部分扛得住差异？"
- **数值家**："有收敛吗？在哪个单位/方案——讨巧的选择是否掩盖了 drift？你的信号要拒绝的 null hypothesis 是什么？"
- **形式理论家**："这个命名对象在这里 well-defined 吗（对称/荷/保护在此设定下真存在吗）？conjecture vs theorem 是什么，摘要区分了吗？"
- **incumbent 社区**："我们早就做得更好——你的 edge 精确是什么，查过我们的 SOTA 吗？"

### 3. Steelman 每个反对意见

反对意见必须是**博学、不同情的专家会签字的**——steelman 绝不 strawman。三个测试：

- **Sting test（刺痛测试）**：若文档现状已干净作答，你大概写了个弱的；磨利到"照它行动需一次编辑"。偶而文档真预答了最强标准反对——把这判定当可疑并 earned it，因为干净全扫正是 strawman pass 也会产出的。
- **Knowledge test（知识测试）**：用审稿人自己的声音写，点出他**知道**而文档忽略的：prior result、标准对照、其社区要求的基准。说不出反对者知道什么=你没模拟他，你在他的座位上模拟你自己。
- **Lead test（领跑测试）**：真审稿人**以标准反对开场**。若你模拟的反对聪明但非标准，先生成标准的；奇特的可作第二行，绝不作替代。

### 4. 验证每个答案在反对者会看的位置

敌意读者按固定顺序读：标题→摘要→图→结论→（仍感兴趣才）反对所在的那一节。"能从散布全文的事实拼出"= FAIL。测试是：反对者在他**实际阅读路径**上、在**反对形成之处或之前**遇到答案。第一次出现在正文中段的 disqualifying caveat 已经输了——报告在摘要就起草了。

Severity：**HIGH** = 未答反对（审稿人会以它开场）或 claim 被项目自己的数据/文件反驳；**MEDIUM** = 正文答了但印象形成处缺席；**LOW** = 答了、可更显著。

### 5. 摘要单独、最后、冷读审计

反复出现的失败：body 诚实，abstract 清干净了所有 caveat。摘要必须携带 (a) 任何 claimed audience 事后发现会视为 disqualifying 的 scope 限制，和 (b) headline claim 的 conjecture-vs-established 标签。冷读它，当作只读它的人——多数审稿人在那里形成框架，有些读者只读摘要。

### 6. 只做最小防御性编辑

Scope 句、null-hypothesis 陈述、prominence 移动（caveat 从正文移到摘要或 scope 段）、headline 数字的单位与约定一致性、conjecture 标签、术语纠正。**不加新 claim、不加新结果、不 hedge-blur**：对反对的正确回应是一句话陈述 claim 的边界，绝不软化它在所有出现处。所有新文本跑 machine-voice/honesty linter；重编译/重渲染并确认干净。

### 7. 写裁决表

写到 `referee_sim_<doc>.md`，放文档旁边：

| audience | objection | axis (correctness/novelty) | answered-where-or-NOT | severity | fix applied |

表是交付物，**即使无需编辑也要写**——它记录审计跑过、覆盖了什么，下一版审计从它开始。

## 三、9 类失败模式目录（自检用）

1. **友好读者**：模拟审稿继承作者框架，只提文档已答的反对；pass 返回 clean，第一个真 outsider 以审计从没生成的反对开场。→ sting test + fresh-context 规则对抗。
2. **Strawman 反对**：每条反对措辞弱到现有文本恰好能答，裁决表填满安慰行，审计认证了它被造出来攻击的那个框架。→ 知识测试对抗。
3. **未读答案**：反对被彻底、诚实地答在反对者从不触及的小节。审稿人在摘要形成反对、在遇到答案前起草报告。prominence 是答案的一部分，脱离阅读路径的答案不是答案。
4. **新颖性-正确性混淆**：每受众一个反对而非两个。文档穷尽防御 correctness，从不陈述相对 incumbent 的进展；或声称进展而 incumbent 社区知道的 prior result 未被交锋。→ 双轴强制对抗。
5. **缺失受众**：被借用其方法/数据集/基准的社区从没拿到一行——恰好是他们的标准反对未答，因为借用援引了他们的标准而审计没注意到。
6. **摘要防火墙**：所有 caveat 在正文，摘要 clean。逐句诚实 pass 逐句确认每个句子、从不见组装。印象在摘要形成；正文是上诉，多数读者从不听上诉。
7. **慈善 outsider**：审计假设第二领域会因工作超出其专长而宽容。事实相反：outsiders 回落到本领域一阶关切，不带 insider 对捷径合理性的上下文。
8. **Hedge-blur**：修复 pass 靠到处削弱 claim 来答反对，而非 scope 一次。文档现在声称得比它证明的少、读作不自信、且仍未答反对。
9. **作者上下文污染**：审计跑在写文档的同一上下文，所以"审稿人"以作者已做的方式判每个反对已答，盲点完好。区别于友好读者：这里连生成良好的反对也收到自我服务的"是否答、答在哪"判定。

## 四、每次都跑的高回报交叉检查

- **Headline 数字单位**：引用的数字是否与文档自身方程定义的单位/约定一致？（失败形态：drift 用讨巧的中间方案单位引用，出来约为文档方程定义值的一半——讨巧选择掩盖了一个 2 因子。）
- **Claim vs 项目自己的文件**：搜索 result notes 里与文档矛盾的陈述。（失败形态：文档断言某量必须随系统尺寸缩小，而项目自己更大尺寸的结果显示它在增大。）
- **必要性语言**：每个 "must / guarantees / ensures"——是推导的，还是希望写成必要性？
- **Null hypothesis**：任何声称的信号（简并、收敛到特殊值、pattern），文档是否陈述了 chance 长什么样、数据为何拒绝它？
- **时序诚实**：若解释是**数据逼出来之后**才找到的，文档可能呈现 theory-then-confirmation；恢复真实顺序。独立的 prior result 仍可作独立引用。
- **标题与摘要层的 conjecture 标签**："candidate / consistent with / designed for" vs 暗示 claim 已确立的语言。

## 五、操作纪律

- **必须在 fresh agent context 跑**——绝不在写文档的上下文。模拟审稿人不得继承作者框架（目录最后一条）。
- 成本 = 每文档一个 agent session。相对一份以你未能模拟的反对开场的审稿报告，它便宜。
- 这是 Gary Klein 意义上的 pre-mortem（HBR, Sept 2007），逐受众跑。
- **首跑产出**：在已完成、fact-verified 的文档上首跑此 pass，可靠地浮出 finding，常是 HIGH 级：scope 陈述恰好缺在外部专家第一眼看的地方；全 caveat 的 body 上一个无 conjecture 语言的摘要；讨巧 headline 收敛图的单位选择；被项目自己文件反驳的 claim。每个都是未来的审稿报告 finding——所以 pass 在 circulation 前而非后跑。

## 七、作者辩护校准（必经步骤，勿跳过）

> **referee-sim 的 finding 不能直接当 HIGH 用。** 本流程生成的是「最强标准反对」，不是「正确 severity」。每个 finding 必须过一遍「作者辩护」——steelman 作者最强立场，区分真实缺陷 / 部分真实 / 可辩护（假阳性），校准 severity 后才进入裁决表。

- **假阳性信号**：反对指向文档**已在显眼位置**（独立章节标题/摘要中段/加粗段落）干净作答的问题 = strawman（对应本流程步骤 3 的 sting test）。
- **真实缺陷信号**：反对指向作者**从未回应的元问题**（如"conditional 到极致是否 = 不可证伪"），而非"已标注但位置不对"的 caveat。
- **实测 precision**（V64 单篇）：4 finding = 1 真实 + 1 部分 + 1 轻微 + 1 假阳性。
- **纪律**：Stage 0 输出分两栏（原 severity + 作者辩护修订后 severity）；只有"过作者辩护仍为真实缺陷"的 finding 保持 HIGH。
