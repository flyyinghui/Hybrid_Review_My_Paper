## 核心判断：表述层（P2/P3）是无限循环，7.5 分应收尾

第 4 轮后 P0/P1 已连续两轮清零，五维度全 7.5，但**又冒出 9 个新 P2 + 31 个新 P3**。
这些新发现全是文献精化/措辞层（如 "[13] Lean manual 缺作者年份"、"NuFit 版本不明确"、
"摘要边界句措辞"），**每轮都能挑出新的，会无限递归**。

**收尾判据（满足即停，不要再跑第 5 轮）**：
1. 评分 ≥ 7.0 且五维度均衡（无 < 6.5 的短板）；
2. P0/P1 连续两轮清零；
3. 核心卖点（0 公理 / 0 sorry / 真编译 / 黄金门控）四轮审查**从未被击穿**；
4. 新发现全部是 P2/P3（表述/文献层），无数学硬伤。

满足以上四点 → 建议"生成 DOCX/PDF 交付版 + 更新 memory"收尾，而非继续修 P2/P3。

## 审稿人误判纠正（必须独立验证，勿盲信）

第 2 轮 technical 报 "restricted-root multiplicity=2 维度不闭合"（声称 A₅ 正根=5，
5+5×2=15≠35）。**独立验证**：A₅ 正根数 = 5×6/2 = **15**，`dim = rank + 正根数×mult = 5 + 15×2 = 35`
完全闭合，论文正确。审稿人把正根数 15 误算成 5。

**教训**：审稿人报"维度不闭合/算术错误"时，先自己重算（正根数、Dynkin index、乘法因子），
skill 里已有 `reviewer-arithmetic-false-positive-verification` 规则，此处是又一实例（正根计数错误）。

## 批量修复时的两个陷阱

1. **转换表算术错误连带**：加归一化转换表（B_6 → T_χ=B_6/2 → 3(B−L)）时，
   N_R 的 `3(B−L)` 列误写 −3/2，应为 −3（3×(−1)）。三个审稿人独立抓到。
   教训：任何"三列转换表"生成后，逐行验证第三列 = 系数 × 第一列。
2. **"孤儿值"未真正消除**：把 35/2 移进 status ledger 表，但它仍无编号公式，
   审稿人判定"同样的孤儿值模式，只是搬到了 ledger 里"。教训：审稿人要求"编号或删除"时，
   必须真编号（inline 定义恒等式标注"非谱隙"），不能只搬位置。
